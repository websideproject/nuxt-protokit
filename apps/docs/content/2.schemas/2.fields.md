# Field Types

Every key in `fields` — on a prototype or on a collection — is a `FieldDef`. All built-in types share one definition; each type reads the options that apply to it.

![Every built-in field type in one form: text, number, select, range, tags, toggle, segmented, rating, date, color and textarea](/screenshots/field-types-1440.png)

## Common properties

```typescript
interface SimpleFieldDef<T = any> {
  type:         'number' | 'text' | 'textarea' | 'select' | 'range' | 'tags'
              | 'date' | 'toggle' | 'segmented' | 'rating' | 'color'
  label:        string | ((value: T) => string)  // a function receives the current value
  default:      T            // required — the value the field reads until it is set (never written to Y.js)
  placeholder?: string       // text, number, textarea, select, tags, date
  help?:        string       // small text below the input
  hint?:        string       // small text beside the label
  leading?:     string       // number only — e.g. '$'
  trailing?:    string       // number only — e.g. 'people'
  min?:         number       // number, range
  max?:         number       // number, range, rating (stars)
  step?:        number       // number, range
  options?:     Array<string | { label: string, value: any, icon?: string }>  // select, segmented
  rangeLabels?: { min: string, max: string }    // range only
  showWhen?:    (values: Record<string, any>) => boolean
  format?:      'money' | 'percent' | 'number' | 'date' | ((v: T) => string)  // used by ProtoCrudTable / ProtoDetailCard
  deep?:        boolean      // compare by value (JSON) instead of identity — set it for object/array values
  permissions?: FieldPermissions  // see Permissions
}
```

`options` accepts plain strings (`['USD', 'EUR']`) or `{ label, value }` objects.

## `text`

Single-line text input.

```typescript
name: { type: 'text', label: 'Full Name', default: '', placeholder: 'e.g. Jane Smith' }
```

## `number`

Numeric input. Stored as a JavaScript number.

```typescript
mrr: { type: 'number', label: 'MRR', default: 10000, leading: '€', trailing: '/mo' }
```

## `textarea`

Multi-line text for notes, descriptions, free-form content.

```typescript
notes: { type: 'textarea', label: 'Notes', default: '', placeholder: 'Key observations…' }
```

## `select`

Dropdown (`USelectMenu`) from a fixed list of options.

```typescript
category: {
  type: 'select',
  label: 'Category',
  options: [
    { value: 'direct',     label: 'Direct Competitor' },
    { value: 'indirect',   label: 'Indirect Competitor' },
    { value: 'substitute', label: 'Substitute' },
  ],
  default: 'direct',
}
```

## `segmented`

Segmented button group (radio-style). Better UX than `select` for 2–5 options.

```typescript
fundingPath: {
  type: 'segmented',
  label: 'Funding Path',
  options: [
    { value: 'bootstrap', label: 'Bootstrap' },
    { value: 'vc',        label: 'VC-Backed' },
  ],
  default: 'bootstrap',
}
```

## `toggle`

Boolean on/off switch.

```typescript
includeVat: { type: 'toggle', label: 'Include VAT', default: false }
```

## `range`

Slider. Set `min`, `max`, and optionally `step`. With `rangeLabels`, the ends are labelled and the current value is shown between them.

```typescript
willingness: {
  type: 'range',
  label: 'Willingness to Pay',
  min: 0,
  max: 10,
  step: 1,
  default: 5,
  rangeLabels: { min: 'None', max: 'Would pay today' },
}
```

## `rating`

Star rating, 1 to `max` (5 when omitted). Stored as a number; clicking the current star again sets it to `0`.

```typescript
satisfaction: { type: 'rating', label: 'Overall Satisfaction', max: 5, default: 3 }
```

## `color`

Native colour picker plus a text input. Stored as a hex string.

```typescript
brandColor: { type: 'color', label: 'Brand Color', default: '#6366f1' }
```

## `date`

Date input (`<UInput type="date">`). Stored as a `YYYY-MM-DD` string.

```typescript
launchDate: { type: 'date', label: 'Target Launch Date', default: '' }
```

## `tags`

Multi-value tag input — Enter adds a tag, duplicates are ignored. Stored as `string[]`, and always compared by value, so you do not need `deep: true`.

```typescript
painPoints: {
  type: 'tags',
  label: 'Pain Points',
  default: [],
  placeholder: 'Add a pain point and press Enter…',
}
```

## `linked-responses`

One textarea per item of another collection — for example an answer per question inside each interview record. It renders wherever the field is used: in a prototype's form or in a collection's add/edit form.

```typescript
// In the `interviews` collection's fields:
responses: {
  type: 'linked-responses',
  label: 'Responses',
  default: [],
  sourceCollection: 'questions',            // key of the collection that provides the prompts
  sourceLabel: item => item.text,           // text shown above each textarea
  sourceBadge: item => item.category,       // optional badge next to it
  answerPlaceholder: 'What did they say?',  // optional
  answerRows: 3,                            // optional, default 2
}
```

The stored value is `Array<{ sourceId: string, answer: string }>`. `sourceId` is the source item's `id` (or its index when it has none). The source items come from the prototype's collections, so the field needs a `ProtoTool` / dashboard that has the `sourceCollection` collection.

## Conditional visibility

`showWhen` receives the current field values (plain values, not refs) and hides the field when it returns `false`:

```typescript
showAdvanced: { type: 'toggle', label: 'Show advanced options', default: false },
advancedOptions: {
  type: 'textarea',
  label: 'Advanced Options',
  default: '',
  showWhen: values => values.showAdvanced === true,
},
```

A hidden field keeps its stored value.

## Columns

The form is a grid with `defaultCols` columns (2 when omitted); a section's `cols` overrides it. Every field takes one cell, except `linked-responses`, which spans the full row. There is no per-field column span.

```typescript
defaultCols: 3,
sections: [
  { title: 'Financial Inputs', cols: 2, fields: ['revenue', 'expenses', 'notes'] },
],
```

## Custom field types

A type of the form `namespace:name` renders a component registered with `defineProtokitExtension`. Its `props` are passed to the component. See [Custom Fields & Viz](/advanced/extensibility).

## Schema migration

**Adding a new field** requires no migration — documents that never stored it read its `default`.

**Renaming a field, changing its type, or transforming values** requires bumping `version` and adding an entry to `migrations`. Each key is the **target version** — the runner steps from the stored version up to current, applying each function in order:

```typescript
definePrototype({
  key: 'my-tool',
  title: 'My Tool',
  shortTitle: 'My Tool',
  description: '',
  icon: 'i-lucide-wrench',
  version: 3,
  migrations: {
    // v0 → v1: renamed 'revenue' → 'monthlyRevenue' (destructure out the old field)
    1: ({ revenue, ...rest }) => ({ ...rest, monthlyRevenue: revenue ?? 0 }),
    // v1 → v2: added 'currency', no transform needed — it reads its default
    // v2 → v3: changed 'monthlyRevenue' from a raw number to cents
    3: ({ monthlyRevenue, ...rest }) => ({ ...rest, monthlyRevenue: Math.round((monthlyRevenue ?? 0) * 100) }),
  },
  fields: {
    monthlyRevenue: { type: 'number', label: 'Monthly Revenue (cents)', default: 0 },
    currency:       { type: 'select', label: 'Currency', default: 'USD', options: ['USD', 'EUR'] },
  },
})
```

Each step function receives every value stored in the prototype's `Y.Map` — including fields the current schema no longer has, so a step can read the field it replaces — with no defaults filled in. Only keys the current schema defines are written back, in a single transaction, together with the new version number. Under `usePrototype` / `ProtoTool` the field migrations run once IndexedDB has loaded the stored data, and are skipped on every later load. Version steps with no entry (like v2 above) are skipped.
