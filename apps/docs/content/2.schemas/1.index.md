# Schema Overview

A `PrototypeSchema` is a plain TypeScript object that fully describes a tool. It is the single source of truth for rendering, computation, and persistence.

## Full type signature

```typescript
interface PrototypeSchema {
  // Identity and display
  key:          string    // unique across all tools — also the default Y.js doc key
  title:        string
  shortTitle:   string
  description:  string
  icon:         string    // Iconify icon, e.g. 'i-lucide-calculator'
  tags?:        string[]

  // Form
  fields:       Record<string, FieldDef>  // every input, keyed by name
  sections?:    SectionDef[]              // optional grouping of those fields into cards
  defaultCols?: 1 | 2 | 3 | 4             // grid columns of the form (default 2)

  // CRUD lists (Y.Arrays)
  collections?: Record<string, CollectionSchema>

  // Computed values (not stored in Y.js)
  derived?:     Record<string, DerivedDef>

  // Display
  results?:        ResultSectionDef[]     // titled cards with a badge and stat tiles
  visualizations?: VizDef[]
  cards?:          CardDef[]

  // Cross-tool data flow
  produces?:    Record<string, 'number' | 'string' | 'boolean' | 'string[]' | 'object' | 'object[]'>
  consumes?:    Record<string, string>    // localAlias → 'sourceSchemaKey.producedKey'
  connections?: ConnectionsDef            // typed only — read by useProtoConnections, not by usePrototype

  // Action toolbar
  actions?:     ProtoAction[]

  // Custom layout (replaces the default sequential rendering)
  layout?:      DashboardLayout

  // Stored-data migrations
  version?:     number
  migrations?:  Record<number, (data: Record<string, any>) => Record<string, any>>
}
```

`definePrototype` requires the display fields. For a storage-only schema without them, use
[`defineHeadlessSchema`](/advanced/headless-mode#defineheadlessschema).

## Key groupings

### `fields` and `sections`

**`fields`** holds every input. Without `sections`, the form renders them in one card, headed by the schema's `title` and `description`:

```typescript
fields: {
  revenue: { type: 'number', label: 'Monthly Revenue (€)', default: 10000 },
  costs:   { type: 'number', label: 'Monthly Costs (€)',   default: 6000 },
  margin:  { type: 'number', label: 'Target Margin (%)',   default: 30 },
}
```

**`sections`** groups those fields into separate cards. A section lists field **keys** from `fields`; it does not define fields of its own:

```typescript
fields: {
  recurring: { type: 'number', label: 'Recurring Revenue (€)', default: 0 },
  oneTime:   { type: 'number', label: 'One-Time Revenue (€)',  default: 0 },
  fixed:     { type: 'number', label: 'Fixed Costs (€)',       default: 0 },
  variable:  { type: 'number', label: 'Variable Costs (€)',    default: 0 },
},
sections: [
  { title: 'Revenue', icon: 'i-lucide-trending-up', cols: 2, fields: ['recurring', 'oneTime'] },
  { title: 'Costs',   icon: 'i-lucide-wallet',      cols: 2, fields: ['fixed', 'variable'] },
],
```

```typescript
interface SectionDef {
  title:        string
  icon?:        string
  description?: string
  fields:       string[]        // keys into schema.fields
  cols?:        1 | 2 | 3 | 4   // falls back to schema.defaultCols
}
```

When `sections` is set, a field that no section lists is not rendered (its value is still stored and available to `derived`).

### `results`

An array of result cards. Each renders below the form with its title, an optional badge, and a grid of stat tiles:

```typescript
import { formatMoney, formatPercent } from '#protokit/utils/formatters'

results: [
  {
    title: 'Profitability',
    statCols: 3,
    badge: ({ derived }) =>
      derived.margin >= 30
        ? { label: 'Healthy Margin', color: 'success' }
        : { label: 'Low Margin',     color: 'warning' },
    stats: ({ derived }) => [
      { label: 'Gross Profit',   value: formatMoney(derived.grossProfit) },
      { label: 'Margin',         value: formatPercent(derived.margin) },
      { label: 'Annual Revenue', value: formatMoney(derived.annualRevenue) },
    ],
  },
],
```

```typescript
interface ResultSectionDef {
  title:     string
  icon?:     string
  showWhen?: (ctx: ComputeContext) => boolean
  badge?:    (ctx: ComputeContext) => { label: string, color: string } | null
  stats:     (ctx: ComputeContext) => StatItem[]
  statCols?: 2 | 3 | 4    // default 4
}
```

Returning `null` from `badge` hides it. When `showWhen` returns `false`, the default layout skips the card; a dashboard layout shows the card's title with "Not enough data yet."

### `actions`

```typescript
actions: [
  { type: 'copy-text',       id: 'copy',   label: 'Copy Summary',  icon: 'i-lucide-clipboard', text: ctx => `…` },
  { type: 'export-markdown', id: 'export', label: 'Export Report', icon: 'i-lucide-download',  content: ctx => `# …`, filename: 'report.md' },
  { type: 'reset',           id: 'reset',  label: 'Reset',         icon: 'i-lucide-trash-2' },
]
```

`text` and `content` receive `(ctx, collectionArrays)`. `reset` clears the fields and every collection straight away — there is no confirmation step. See [Actions toolbar](/schemas/visualizations#actions-toolbar).

## The `ComputeContext` type

`derived[x].compute`, the `results` callbacks, every visualization data function, `showWhen` on results and visualizations, card callbacks, and dashboard tab badges all receive a `ComputeContext`:

```typescript
interface ComputeContext {
  fields:      Record<string, any>   // current field values
  derived:     Record<string, any>   // derived values (in definition order)
  connections: Record<string, any>   // values from upstream `produces`, by `consumes` alias
  collections: Record<string, any[]> // CRUD collection items
}
```

Field-level `showWhen` is the exception: it receives the plain field values (`(values) => boolean`).

## `StatItem` format

```typescript
interface StatItem {
  label:       string
  value:       string | number   // shown as-is — format it yourself
  subLabel?:   string            // small text under the value
  valueClass?: string            // extra classes on the value
  bgClass?:    string            // extra classes on the tile
}
```

Stat values are not formatted for you. Use the helpers from `#protokit/utils/formatters`:

| Helper | Input | Example output |
|--------|-------|----------------|
| `formatMoney(v)` | `number` | `$12K` (compact by default), `$950`, `$1.2M` |
| `formatMoney(v, { compact: false })` | `number` | `$12,345` |
| `formatPercent(v, decimals = 1)` | `number` (0–100) | `23.5%` |
| `formatPercentFromRatio(v, decimals = 1)` | `number` (0–1) | `23.5%` |
| `formatNumber(v)` | `number` | `1,234` |
| `formatDate(v)` | ISO string or `Date` | `3/14/2026` |

All of them format with the `en-US` locale, so a server render and the browser agree. `formatMoney` always uses `$`.
