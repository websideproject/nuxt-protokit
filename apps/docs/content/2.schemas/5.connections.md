# Connections — Produces & Consumes

Tools rarely exist in isolation. A cost estimator produces a monthly burn figure that a runway calculator needs. A scoring tool produces aggregated ratings that a summary dashboard needs. The **produces/consumes** system wires these tools together reactively and offline.

## How it works

```
┌────────────────────────────┐  Y.Map 'outputs:cost-estimator'  ┌─────────────────────────────────┐
│  cost-estimator schema     │  ──────────────────────────────► │  runway schema                  │
│                            │                                  │                                 │
│  derived: monthly          │                                  │  consumes:                      │
│  produces:                 │                                  │    upstreamCost:                │
│    monthly: 'number'       │                                  │      'cost-estimator.monthly'   │
└────────────────────────────┘                                  └─────────────────────────────────┘
```

1. The upstream tool writes `derived.monthly` (say `12400`) into `Y.Map 'outputs:cost-estimator'` whenever it changes
2. The downstream tool reads that map and exposes the value as `connections.upstreamCost`
3. The downstream tool's `derived` values, `results`, `visualizations`, `cards` and `actions` receive `ctx.connections.upstreamCost = 12400`
4. Both tools must use the **same `Y.Doc`** — then this happens instantly and fully offline

## Declaring `produces`

```typescript
// cost-estimator schema
derived: {
  monthly: { compute: ({ fields }) => fields.salaries + fields.tooling },
  annual:  { compute: ({ derived }) => derived.monthly * 12 },
},
produces: {
  monthly: 'number',   // key of `derived` → its type
  annual:  'number',
},
```

Each key of `produces` names a **derived value**; the value declares its type (`'number' | 'string' | 'boolean' | 'string[]' | 'object' | 'object[]'`) for readers of the schema. Only derived values are written — to export a raw field or a collection, add a derived value that returns it. A value that is `undefined` is not written.

## Declaring `consumes`

```typescript
// runway schema
consumes: {
  upstreamCost:   'cost-estimator.monthly',  // localAlias: 'sourceSchemaKey.producedKey'
  upstreamAnnual: 'cost-estimator.annual',
},
```

Format: `'sourceTool.sourceKey'` where:
- `sourceTool` — the `key` of the schema that declares `produces`
- `sourceKey` — the key inside that schema's `produces` map

Consumed values appear in `ctx.connections` under the local alias.

## Using connections in `derived`

```typescript
// runway schema
derived: {
  effectiveMonthlyCost: {
    compute: ({ fields, connections }) =>
      // Use the upstream value when available, fall back to a local field
      connections.upstreamCost ?? fields.localMonthlyCost,
  },
  runwayMonths: {
    compute: ({ fields, derived }) =>
      derived.effectiveMonthlyCost > 0
        ? Math.floor(fields.availableFunds / derived.effectiveMonthlyCost)
        : Infinity,
  },
},
```

Always guard against `undefined` connections — the upstream tool may not have been opened yet, or may have no data. A derived value that is consumed by its own tool is fine too: an output is only written when its value changes.

## Sharing a Y.Doc

The produces/consumes flow only works inside one `Y.Doc`. Each tool keeps its data under its own schema key:

```
Y.Doc 'workspace-xyz'
├── Y.Map   'cost-estimator'               ← cost-estimator fields
├── Y.Map   'outputs:cost-estimator'       ← cost-estimator produces
├── Y.Array 'cost-estimator:line-items'    ← a cost-estimator collection
├── Y.Map   'runway'                       ← runway fields
└── Y.Map   'outputs:runway'               ← runway produces
```

Pass the same document to each tool:

```vue
<script setup lang="ts">
const { doc, isReady } = useProtoDoc('workspace-xyz')
</script>

<template>
  <ClientOnly>
    <template v-if="isReady">
      <ProtoTool :schema="costEstimator" :doc="doc" />
      <ProtoTool :schema="runway" :doc="doc" />
    </template>
  </ClientOnly>
</template>
```

or `usePrototype(schema, { existingDoc: doc })` in your own components. A tool given a document treats it as already loaded, so wait for that document's `isReady` before rendering the tools. When each tool opens its own document (the default), `consumes` always reads empty maps.

### Separate documents: `useProtoConnections`

`useProtoConnections` is a standalone helper for reading fields out of other documents. It takes a `ConnectionsDef` and a function that returns an open `Y.Doc` by key, and observes the named fields of a `Y.Map` in each:

```typescript
const connections = useProtoConnections(
  {
    pricing: { sourceDocKey: 'proto:pricing', sourceMapKey: 'pricing', fields: ['arpu', 'plan'] },
  },
  key => documentCache.get(key) ?? null,   // import { documentCache } from '#protokit/composables/useProtoDoc'
)

connections.pricing.value.arpu
```

It only sees documents that are already open, and `usePrototype` does not call it — the schema's `connections` key is typed but not read by any built-in. Prefer one shared document.

## Example connection graph

A project management toolkit might have:

```
time-tracker   ──produces──► cost-estimator    (hourly totals)
cost-estimator ──produces──► runway            (monthly burn)
cost-estimator ──produces──► profitability     (monthly burn)
revenue-model  ──produces──► profitability     (monthly revenue)
profitability  ──produces──► investor-summary  (margin, breakeven)
```

Each tool is independently useful. The connections make them greater than the sum of their parts — and the whole graph works offline.

## Listing a tool's upstream and downstream tools

There is no built-in graph helper, but `consumes` holds everything you need:

```typescript
import type { PrototypeSchema } from '#protokit/types'

function upstreamOf(schema: PrototypeSchema): string[] {
  return [...new Set(Object.values(schema.consumes ?? {}).map(path => path.split('.')[0]))]
}

function downstreamOf(key: string, all: PrototypeSchema[]): string[] {
  return all.filter(s => upstreamOf(s).includes(key)).map(s => s.key)
}

upstreamOf(runwaySchema)                  // ['cost-estimator']
downstreamOf('cost-estimator', allSchemas) // ['runway', 'profitability']
```
