# Derived & Computed Values

Derived values turn raw field inputs into meaningful numbers, strings, dates, or structures. They update reactively whenever their dependencies change and are available in results, visualizations, and the produces/consumes graph.

![Derived SaaS metrics: ARR, LTV, LTV:CAC and quick ratio computed from six inputs, with health badges and a benchmark](/screenshots/saas-dashboard-1440.png)

## Basic syntax

```typescript
derived: {
  myValue: {
    compute: (ctx: ComputeContext) => { /* return any value */ },
  }
}
```

The `compute` function is **synchronous** and **pure** — it should have no side effects.

## The `ComputeContext`

```typescript
interface ComputeContext {
  fields:      Record<string, any>   // unwrapped current field values
  derived:     Record<string, any>   // earlier derived values (in definition order)
  connections: Record<string, any>   // always {} inside derived — see below
  collections: Record<string, any[]> // CRUD collection items
}
```

::callout{color="amber" icon="i-lucide-triangle-alert"}
**Order matters.** Derived values are computed in the order they are defined. A derived value can reference earlier entries via `derived.earlierKey`, but referencing a later key returns `undefined`. Define dependencies before dependants.
::

## Referencing other derived values

```typescript
derived: {
  // Step 1 — contributionMargin must be defined BEFORE breakEvenUnits
  contributionMargin: {
    compute: ({ fields }) => fields.pricePerUnit - fields.costPerUnit,
  },

  // Step 2 — can safely reference derived.contributionMargin
  breakEvenUnits: {
    compute: ({ fields, derived }) =>
      derived.contributionMargin > 0
        ? Math.ceil(fields.fixedCosts / derived.contributionMargin)
        : Infinity,
  },

  // Step 3 — references two earlier derived values
  profitAtForecast: {
    compute: ({ fields, derived }) =>
      derived.contributionMargin * fields.expectedUnits - fields.fixedCosts,
  },
}
```

## Referencing upstream connections

When a tool declares `consumes`, the resolved values are in `ctx.connections` of the **`ComputeContext` that results, visualizations, cards and actions receive**:

```typescript
// schema declares:
consumes: { pricingArpu: 'pricing.arpu' },

results: [
  {
    title: 'Lifetime Value',
    stats: ({ fields, connections }) => [
      {
        label: 'LTV',
        value: connections.pricingArpu
          ? formatMoney(connections.pricingArpu / (fields.churnRate / 100))
          : '—',
      },
    ],
  },
],
```

::callout{color="amber" icon="i-lucide-triangle-alert"}
Inside `derived[x].compute`, `connections` is currently always `{}` — `usePrototype` computes derived values before it reads the consumed outputs. Use consumed values in `results`, `visualizations`, `cards` and `actions`, not in `derived`.
::

If the upstream tool has not produced data yet (or does not share the document), `connections.pricingArpu` is `undefined`. Always guard against this.

## Referencing collections

```typescript
derived: {
  interviewCount: {
    compute: ({ collections }) => collections.interviews?.length ?? 0,
  },
  avgSentiment: {
    compute: ({ collections }) => {
      const interviews = collections.interviews ?? []
      if (!interviews.length) return null
      const total = interviews.reduce((sum, i) => sum + (i.sentiment ?? 0), 0)
      return total / interviews.length
    },
  },
}
```

## The `deps` hint

The `deps` array is an optional documentation hint listing which fields/derived keys this computation reads. It has **no effect on reactivity** — `useProtoDerived` recomputes all derived values whenever any field or collection changes. Use it as a readability aid:

```typescript
breakEvenUnits: {
  deps: ['fixedCosts', 'contributionMargin'],
  compute: ({ fields, derived }) => …,
}
```

## Formatting

`DerivedDef` has an optional `format` (`'money' | 'percent' | 'number' | 'date' | (v) => string`), but no built-in component reads it — derived values are never displayed on their own. They are shown through `results`, `cards` and visualizations, which take the values you return. Format there, with the helpers from `#protokit/utils/formatters`:

```typescript
import { formatMoney, formatNumber, formatDate } from '#protokit/utils/formatters'

derived: {
  monthlyBurn: {
    compute: ({ fields }) => fields.rent + fields.salaries + fields.software,
  },
  runwayMonths: {
    compute: ({ fields, derived }) =>
      derived.monthlyBurn > 0
        ? Math.floor(fields.totalFunds / derived.monthlyBurn)
        : Infinity,
  },
  runwayDate: {
    compute: ({ derived }) => {
      if (!isFinite(derived.runwayMonths)) return null
      const d = new Date()
      d.setMonth(d.getMonth() + derived.runwayMonths)
      return d.toISOString().split('T')[0]
    },
  },
},

results: [
  {
    title: 'Runway',
    stats: ({ derived }) => [
      { label: 'Monthly Burn', value: formatMoney(derived.monthlyBurn) },
      { label: 'Runway',       value: `${formatNumber(derived.runwayMonths)} months` },
      { label: 'Runs out',     value: derived.runwayDate ? formatDate(derived.runwayDate) : '—' },
    ],
  },
],
```

See [the formatter table](/schemas#statitem-format) for what each helper prints. The raw computed value is what later derived values, `produces`, and visualizations receive.

## Using derived values in `results`

`results` is an array of cards. Each card's `badge` and `stats` receive the full `ComputeContext`, so derived values are directly accessible:

```typescript
results: [
  {
    title: 'Unit Economics',
    badge: ({ derived }) =>
      derived.ltvCacRatio >= 3
        ? { label: 'Healthy LTV:CAC', color: 'success' }
        : { label: 'LTV:CAC Too Low', color: 'error' },

    stats: ({ derived }) => [
      { label: 'LTV',     value: formatMoney(derived.ltv) },
      { label: 'CAC',     value: formatMoney(derived.cac) },
      { label: 'LTV:CAC', value: derived.ltvCacRatio.toFixed(1) },
    ],
  },
],
```

## Using derived values in `produces`

`produces` exports derived values to downstream tools. Each key is a key of `derived`, and the value is its type:

```typescript
produces: {
  arpu:          'number',
  mrrProjection: 'object[]',
}
```

Whenever a derived value changes, it is written to the `Y.Map 'outputs:<schema.key>'` under the same key. Only derived values can be produced — to export a raw field, add a derived value that returns it. See [Connections](/schemas/connections).
