# Visualizations & Layouts

![The built-in visualizations: stat cards with sparklines, line and area charts, bar, pie, progress, funnel, benchmark and timeline](/screenshots/charts-1440.png)

## Built-in visualization types

Add a `visualizations` array to your schema to render charts and tables below the results. Every entry has the same outer shape:

```typescript
{
  type:      'bar-chart',            // which visualization
  title?:    'Monthly Breakdown',    // optional heading
  showWhen?: ctx => boolean,         // hide it until there is something to show
  config: {
    type: 'bar-chart',               // repeats the outer type — required by the TypeScript types
    // …the options of that type
  },
}
```

The functions inside `config` receive the `ComputeContext`. All types are also available as standalone `Viz*` components.

| `type` | Component | Best for |
|--------|-----------|----------|
| `progress` | `VizProgressBar` | Single metric vs. goal |
| `benchmark` | `VizBenchmarkBar` | Position relative to a median |
| `bar-chart` | `VizBarChart` | Ranked or categorical values |
| `line-chart` | `VizLineChart` | Single time-series trend |
| `area-chart` | `VizAreaChart` | Multi-series trends with fill |
| `pie-chart` | `VizPieChart` | Part-of-whole distribution |
| `donut-chart` | `VizPieChart` (donut) | Part-of-whole with centre total |
| `funnel-chart` | `VizFunnelChart` | Step-by-step conversion |
| `stat-cards` | `VizStatCards` | KPI overview with trends |
| `comparison-table` | `VizComparisonTable` | Side-by-side attribute comparison |
| `feature-matrix` | `VizFeatureMatrix` | Feature coverage matrix |
| `timeline` | `VizTimeline` | Dated milestone list |

### `progress`

A horizontal progress bar. `value` is divided by `max` (default `100`). `thresholds` pick the bar's colour and label: the last threshold the value has reached wins. A threshold's `color` is a Nuxt UI colour name (`'error'`, `'warning'`, `'success'`, …) or a background class of your own (`'bg-emerald-500'`).

```typescript
{
  type: 'progress',
  title: 'Progress to Break-Even',
  config: {
    type: 'progress',
    value: ({ fields, derived }) => (fields.expectedUnits / derived.breakEvenUnits) * 100,
    max: 100,
    label: ({ derived }) => `${derived.breakEvenUnits} units to break even`,
    thresholds: [
      { value: 0,   color: 'bg-error',   label: 'Below break-even' },
      { value: 100, color: 'bg-success', label: 'Profitable' },
    ],
  },
}
```

### `benchmark`

A bar with a median marker — where you stand against an industry figure. The bar is green at or above the median.

```typescript
{
  type: 'benchmark',
  title: 'LTV:CAC vs Industry',
  config: {
    type: 'benchmark',
    value: ({ derived }) => derived.ltvCacRatio,
    median: 3,
    min: 0,       // default 0
    max: 10,      // default 100
    label: 'LTV:CAC',
    unit: 'x',
  },
}
```

### `bar-chart`

Bars from a list of `{ label, value, color? }` items.

```typescript
{
  type: 'bar-chart',
  title: 'Budget by Category',
  config: {
    type: 'bar-chart',
    data: ({ collections }) =>
      [...(collections.categories ?? [])]
        .sort((a, b) => (b.amount ?? 0) - (a.amount ?? 0))
        .map(c => ({ label: c.name, value: c.amount ?? 0 })),
    unit: '$',
    // maxValue: 10000,   // fixes the scale instead of using the largest value
  },
}
```

Copy a collection array before sorting it — `collections.*` are the live item arrays.

### `comparison-table`

Rows of items against a fixed set of columns.

```typescript
{
  type: 'comparison-table',
  title: 'Competitor Comparison',
  config: {
    type: 'comparison-table',
    columns: [
      { key: 'name',    label: 'Competitor' },
      { key: 'pricing', label: 'Pricing' },
      { key: 'freeTier', label: 'Free Tier' },
      { key: 'support', label: 'Support' },
    ],
    rows: ({ collections }) =>
      (collections.competitors ?? []).map(c => ({
        name:     c.name,
        pricing:  c.pricing,
        freeTier: c.hasFree ? 'Yes' : 'No',
        support:  c.support,
      })),
  },
}
```

### `feature-matrix`

A coverage grid of features against entities (plans, competitors). Each cell is `true`, `false` or `'partial'`.

```typescript
{
  type: 'feature-matrix',
  title: 'Plan Feature Matrix',
  config: {
    type: 'feature-matrix',
    features: ['Unlimited users', 'API access', 'SSO', 'Audit log', 'SLA'],
    entities: ({ collections }) =>
      (collections.plans ?? []).map(p => ({
        name: p.name,
        coverage: {
          'Unlimited users': p.unlimitedUsers,
          'API access':      p.api,
          'SSO':             p.sso ? true : 'partial',
          'Audit log':       p.auditLog,
          'SLA':             p.sla,
        },
      })),
  },
}
```

### `line-chart`

A smooth SVG line chart with a gradient fill and optional axes. Accepts a flat array of `{ label, value }` points.

```typescript
{
  type: 'line-chart',
  title: 'Monthly Revenue',
  config: {
    type: 'line-chart',
    data: ({ derived }) => derived.revenueByMonth,  // { label, value }[]
    showAxes: true,
    unit: '$',
    color: 'var(--color-emerald-500)',
    emptyText: 'No revenue yet',
  },
}
```

### `area-chart`

A multi-series SVG area chart. Each series renders its own filled region and line, for comparing trends over the same axis.

```typescript
{
  type: 'area-chart',
  title: 'Revenue vs Target',
  config: {
    type: 'area-chart',
    series: ({ derived }) => [
      { label: 'Actual', data: derived.revenueByMonth, color: 'var(--color-primary-500)' },
      { label: 'Target', data: derived.targetByMonth,  color: 'var(--color-emerald-500)' },
    ],
    showAxes: true,
    unit: '$',
  },
}
```

### `pie-chart` / `donut-chart`

An SVG pie chart with a legend (on unless `showLegend: false`). `donut-chart` renders the donut variant with the total in the centre.

```typescript
{
  type: 'donut-chart',
  title: 'Traffic Sources',
  config: {
    type: 'donut-chart',
    data: ({ derived }) => derived.channelBreakdown,  // { label, value, color? }[]
    unit: '%',
    showLegend: true,
  },
}
```

### `funnel-chart`

A horizontal funnel. Each bar is sized relative to the first step; the conversion from the previous step is shown between bars unless `showConversion: false`.

```typescript
{
  type: 'funnel-chart',
  title: 'Acquisition Funnel',
  config: {
    type: 'funnel-chart',
    data: ({ derived }) => [
      { label: 'Visitors', value: derived.visitors },
      { label: 'Sign-ups', value: derived.signups },
      { label: 'Trial',    value: derived.trials },
      { label: 'Paid',     value: derived.paid },
    ],
    showConversion: true,
  },
}
```

### `stat-cards`

A responsive grid of KPI cards. Each card shows a label, value, optional trend arrow with percentage, and an optional sparkline.

```typescript
{
  type: 'stat-cards',
  config: {
    type: 'stat-cards',
    cols: 3,
    cards: ({ derived }) => [
      {
        label: 'Monthly Revenue',
        value: `$${derived.mrr.toLocaleString('en-US')}`,
        trend: derived.mrrGrowthPct,
        trendLabel: 'vs last month',
        icon: 'i-lucide-dollar-sign',
        color: 'emerald',
        sparkline: derived.mrrHistory,   // number[]
      },
      {
        label: 'Active Users',
        value: derived.activeUsers,
        trend: derived.userGrowthPct,
        icon: 'i-lucide-users',
        color: 'primary',
      },
    ],
  },
}
```

The `color` field accepts `'primary' | 'emerald' | 'rose' | 'amber' | 'violet' | 'sky' | 'neutral'` and controls the icon background, icon tint, and sparkline colour. Pass a locale to `toLocaleString` so the server and browser render the same digits.

### `timeline`

A vertical list of milestones.

```typescript
{
  type: 'timeline',
  title: 'Launch Milestones',
  config: {
    type: 'timeline',
    items: ({ collections }) =>
      (collections.milestones ?? []).map(m => ({
        title:  m.title,
        date:   m.date,
        status: m.done ? 'done' : 'upcoming',   // 'done' | 'current' | 'upcoming'
      })),
  },
}
```

### Custom types

A `type` of the form `namespace:name` renders a component registered with `defineProtokitExtension`; it receives the `config` object and the `context`. See [Custom Fields & Viz](/advanced/extensibility).

## Custom Dashboard Layouts

For tools with tabs, columns and mixed content, the `layout` property takes over the rendering. `ProtoTool` renders a `ProtoDashboard` instead of the default sequence; the action bar still follows it.

### Layout structure

A layout has either `rows` or `tabs`. A row is a grid of 1–4 columns; each item takes one column, or `span` columns:

```typescript
layout: {
  rows: [
    {
      cols: 2,
      items: [
        { type: 'form' },                    // the whole form (or one section: sectionIndex)
        { type: 'stats', resultIndex: 0 },   // results[0]
      ],
    },
    {
      cols: 1,
      items: [{ type: 'viz', vizIndex: 0 }],
    },
    {
      cols: 1,
      items: [{ type: 'collection', collectionKey: 'interviews', view: 'list' }],
    },
  ],
}
```

### Tab layout

`layout.tabs` renders page-level `UTabs`; each tab has its own rows. A tab's `badge` returns `{ label, color }` or `null`, and its `label` is shown on the tab:

```typescript
layout: {
  tabs: [
    {
      id: 'questions',
      label: 'Questions',
      badge: ({ collections }) => collections.questions?.length
        ? { label: String(collections.questions.length), color: 'neutral' }
        : null,
      rows: [
        { cols: 1, items: [{ type: 'collection', collectionKey: 'questions', view: 'list' }] },
      ],
    },
    {
      id: 'interviews',
      label: 'Interviews',
      rows: [
        { cols: 1, items: [{ type: 'collection', collectionKey: 'interviews', view: 'list' }] },
      ],
    },
    {
      id: 'patterns',
      label: 'Patterns',
      rows: [
        { cols: 2, items: [
          { type: 'stats', resultIndex: 0 },
          { type: 'viz',   vizIndex: 0 },
        ] },
      ],
    },
  ],
}
```

### `LayoutItem` types

| `type` | Renders | Props |
|--------|---------|-------|
| `'form'` | `ProtoForm` in a card | `sectionIndex?` — one section, titled; omit for all |
| `'stats'` | A result card (`ProtoStatGrid` + badge) | `resultIndex` (0-based into `results`) |
| `'viz'` | `ProtoViz` in a card | `vizIndex` (0-based into `visualizations`) |
| `'card'` | `ProtoCard` | `cardIndex` (0-based into `cards`) |
| `'collection'` | `ProtoCrudList`, `ProtoCrudTable` or `VizCollectionCalendar` | `collectionKey`, `view: 'list' \| 'table' \| 'calendar'`, `calendarConfig` for `'calendar'` |
| `'tabs'` | Inline `UTabs` | `tabs: { id, label, icon?, items }[]` — items may be `collection` (`view: 'list'`), `stats` or `viz` |
| `'section'` | `ProtoSection` with a slot named `section-<title>` | `title`, `items` (not rendered) |

Every item also takes `span`. A `section` item only renders a titled box around the dashboard's `section-<title>` slot — `ProtoTool` passes no slots, so use it with `ProtoDashboard` directly.

### `span` and `gap`

A row's `cols` (1–4) sets the grid; an item's `span` (2–4) makes it cover that many columns from the `md` breakpoint. Omit `span` for one column. `LayoutRow.gap` is typed but not used.

## Actions toolbar

```typescript
actions: [
  {
    type: 'copy-text',
    id: 'copy-script',
    label: 'Copy Interview Script',
    icon: 'i-lucide-clipboard',
    text: ({ collections }) =>
      (collections.questions ?? [])
        .map((q, i) => `${i + 1}. ${q.text}`)
        .join('\n'),
  },
  {
    type: 'export-markdown',
    id: 'export-summary',
    label: 'Export Summary',
    icon: 'i-lucide-download',
    filename: 'interview-summary.md',   // default 'export.md'
    content: ({ derived }) =>
      `# Interview Summary\n\n**${derived.interviewCount} interviews**\n\n## Pain Points\n- ${derived.painPoints?.join('\n- ')}`,
  },
  {
    type: 'reset',
    id: 'reset',
    label: 'Reset All Data',
    icon: 'i-lucide-trash-2',
  },
]
```

`ProtoActionBar` renders these as outline buttons below the tool when `schema.actions` is set; each action can also take `showWhen(ctx)`. `copy-text` shows "Copied!" for two seconds. `export-markdown` downloads the file. `reset` clears every field and collection immediately, without asking — wrap the tool or use your own button with a confirmation if you need one.
