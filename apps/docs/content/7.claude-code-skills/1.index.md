# Claude Code Skills

`nuxt-protokit` ships a [Claude Code](https://claude.ai/code) skill plugin so Claude has accurate, up-to-date knowledge of the library's APIs — without hallucinating field types, composable signatures, or component props.

## Installation

Run these two commands in Claude Code:

```bash
/plugin marketplace add websideproject/nuxt-protokit
/plugin install nuxt-protokit-skills
```

That's it. Claude will now automatically load the relevant skill context whenever you work with `nuxt-protokit`.

## What the skill covers

The **`nuxt-protokit`** skill provides progressive-loading reference docs across 8 topic areas:

| Topic | Coverage |
|-------|----------|
| **Schema** | `definePrototype`, all 12 field types, `CollectionSchema`, `DerivedDef`, `DashboardLayout`, `ProtoAction` |
| **Composables** | `usePrototype`, `useProtoCollection`, `useProtoDoc`, `useProtoCalendar`, namespace isolation |
| **Components** | `<ProtoTool>`, `<ProtoDashboard>`, `<ProtoCrudModal>`, `<ProtoCalendar>`, `<ProtoViz>`, `<ProtoActionBar>` |
| **Visualizations** | All 12 viz types with full config interfaces and examples |
| **Offline-first** | Y.js + IndexedDB architecture, multi-tab sync, server sync config, encryption |
| **Extensions** | `defineProtokitExtension`, custom field/viz type registration |
| **Headless** | `defineHeadlessSchema`, programmatic usage without UI components |
| **Module authoring** | Building a Nuxt module that ships custom fields/viz via `protokit:register-extension` |

## How it works

Skills are token-efficient — only the relevant reference file is loaded based on what you're working on. Asking about `usePrototype` options? Only `references/composables.md` is loaded. Building a custom viz? Only `references/extensions.md`.

## Source

The skill lives next to the source code in this repository:
