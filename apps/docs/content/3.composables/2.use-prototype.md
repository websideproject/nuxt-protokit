# `usePrototype`

The high-level facade. Combines `useProtoDoc`, `useProtoMap`, `useProtoList`, `useProtoDerived`, `useProtoOutputs` and `useProtoPermissions` into one composable call. Start here when building a custom tool UI.

## Signature

```typescript
function usePrototype(
  schema:   PrototypeSchema,
  options?: {
    docKey?:      string            // defaults to schema.key
    existingDoc?: Y.Doc             // use this doc instead of opening one (skips useProtoDoc)
    namespace?:   string            // prefix for per-user / per-tenant isolation
    disableSync?: boolean           // local-only override, ignores the global serverSync config
    encryption?:  EncryptionConfig  // { password } or { key } — AES-GCM at rest
  }
): UsePrototypeReturn
```

## Return value

```typescript
interface UsePrototypeReturn {
  // Y.js document
  doc:      Y.Doc
  isReady:  Ref<boolean>   // true once IndexedDB has loaded (immediately with existingDoc)

  // Form fields — one Ref per field key
  state:    Record<string, Ref>

  // CRUD collections — one list per collection key
  collections: Record<string, UseProtoListReturn<any>>

  // Computed derived values
  derived:  ComputedRef<Record<string, any>>

  // Compute context (for passing to results/viz functions)
  computeContext: ComputedRef<ComputeContext>

  // Reactive role-guard flags (frontend only — see Permissions)
  fieldPermissions:      Record<string, { canRead: ComputedRef<boolean>, canWrite: ComputedRef<boolean> }>
  collectionPermissions: Record<string, { canRead, canCreate, canUpdate, canDelete: ComputedRef<boolean> }>

  // Actions
  reset(): void   // reset all fields to their defaults and empty every collection
}
```

## Basic usage

```vue
<script setup lang="ts">
const { state, derived, isReady, reset } = usePrototype(mySchema)
</script>

<template>
  <div v-if="!isReady">Loading…</div>
  <div v-else>
    <UFormField label="MRR">
      <UInputNumber v-model="state.mrr.value" />
    </UFormField>
    <p>ARR: {{ derived.arr }}</p>
    <UButton @click="reset">Reset</UButton>
  </div>
</template>
```

`state` is a plain object of refs, so templates need `.value` (`state.mrr.value`). `derived` is a single computed and unwraps in templates.

## Field refs

Each field in the schema becomes a `Ref` inside `state`:

```typescript
const { state } = usePrototype(schema)

// Read
console.log(state.mrr.value)

// Write — goes to the Y.Map, then IndexedDB and other tabs
state.mrr.value = 15000
```

A write updates the document's `Y.Map`, which IndexedDB persists and the `BroadcastChannel` sends to other tabs. With `serverSync` on, the full document is pushed to the server 30 seconds after the last change.

## Collections

Each collection is a `useProtoList` result. Its operations take **indexes** into `items`:

```typescript
const { collections } = usePrototype(schema)

// 'interviews' maps to schema.collections.interviews
const interviews = collections.interviews

interviews.items.value                   // Ref<Item[]> — reactive list, defaults merged in
interviews.add({ id: crypto.randomUUID(), name: 'Alice', notes: '…' })
interviews.update(0, { notes: 'updated' })  // merges into the item at index 0
interviews.remove(0)
interviews.move(0, 2)                    // move the item at index 0 to index 2
interviews.count.value                   // ComputedRef<number>
interviews.reset()                       // remove every item
```

`add` stores the item as given — protokit does not add an `id`. Search and sort live in [`useProtoCollection`](/composables/use-proto-collection); for a prototype's collection, filter `items.value` yourself.

## Derived values

```typescript
const { derived } = usePrototype(schema)

// derived is a ComputedRef — access .value
console.log(derived.value.ltvCacRatio)  // automatically recomputed when fields change
```

## ComputeContext

Pass `computeContext.value` to your own result / visualization rendering:

```typescript
const { computeContext } = usePrototype(schema)

const result = schema.results?.[0]
const badge = computed(() => result?.badge?.(computeContext.value) ?? null)
const stats = computed(() => result?.stats(computeContext.value) ?? [])
```

## Custom doc key

```typescript
// Two independent instances of the same schema — separate storage
const toolA = usePrototype(breakEvenSchema, { docKey: 'break-even-scenario-a' })
const toolB = usePrototype(breakEvenSchema, { docKey: 'break-even-scenario-b' })
```

## Per-user / per-tenant isolation

Pass a `namespace` to scope the IndexedDB store and BroadcastChannel to a specific user, tenant, or workspace. The namespace is prepended to the doc key: `proto:<namespace>:<schema.key>`.

```typescript
// Tenant-shared: all users in the org see the same document
const { state } = usePrototype(mySchema, { namespace: tenantId })

// Private per user within a tenant
const { state } = usePrototype(mySchema, { namespace: `${tenantId}:${userId}` })
```

The key is resolved once, when the composable runs. See the [Multi-tenant & per-user isolation](/offline-first/multi-tenant-isolation) guide for switching namespaces, cleanup on logout, and security considerations.

## Readiness guard

`isReady` becomes `true` once IndexedDB has finished loading the stored data. Guard renders behind it to avoid a flash of default values:

```vue
<template>
  <ClientOnly>
    <div v-if="!isReady" class="animate-pulse">Loading saved data…</div>
    <ProtoForm v-else :fields="schema.fields" :model="state" :sections="schema.sections" />
  </ClientOnly>
</template>
```

## `reset()`

Writes every field's `default` back to the document and removes all items from every collection, in one go. To reset only the fields, set them yourself.

```typescript
const { reset } = usePrototype(schema)

function handleReset() {
  if (confirm('Reset all values and remove all items?')) {
    reset()
  }
}
```

## Sharing a Y.Doc between tools

When several tools should share one document — for [produces/consumes](/schemas/connections), or one store per workspace — open the document once and pass it as `existingDoc`:

```typescript
const { doc, isReady } = useProtoDoc(`workspace-${workspaceId}`)

const estimator = usePrototype(estimatorSchema, { existingDoc: doc })
const runway    = usePrototype(runwaySchema,    { existingDoc: doc })
```

Each tool keeps its data under its own schema key inside the document (`Y.Map '<key>'`, `Y.Array '<key>:<collection>'`, `Y.Map 'outputs:<key>'`), so they never collide. With `existingDoc`, `usePrototype` skips `useProtoDoc`: its `isReady` is `true` straight away and `namespace`, `encryption` and `disableSync` are ignored — use the `isReady` of the `useProtoDoc` call that opened the document, pass `encryption` / `disableSync` to it, and put any namespace into its key (`useProtoDoc(\`${tenantId}:workspace-${workspaceId}\`)`).
