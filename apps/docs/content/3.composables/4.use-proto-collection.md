# `useProtoCollection`

High-level CRUD for a single collection. Opens (or reuses) a document, wraps `useProtoList` with search, sort and count, and resolves the collection's permission guards.

## Signature

```typescript
function useProtoCollection(
  schema:   CollectionSchema,
  options?: {
    docKey?:      string   // default: `collection-${schema.key}`
    existingDoc?: Y.Doc    // store the collection in this doc instead
    disableSync?: boolean  // local-only override
  },
): UseProtoCollectionReturn
```

The items live in `Y.Array '<schema.key>'` of that document.

## Return value

```typescript
interface UseProtoCollectionReturn {
  doc:      Y.Doc
  isReady:  Ref<boolean>               // true once IndexedDB has loaded (immediately with existingDoc)

  // Reactive state
  items:    Ref<any[]>                 // all items, defaults merged in
  filtered: ComputedRef<any[]>         // search-filtered items
  sorted:   ComputedRef<any[]>         // search-filtered + sorted items
  count:    ComputedRef<number>        // total item count

  // Search and sort
  search:    Ref<string>               // bind to a search input
  sortKey:   Ref<string>               // '' = insertion order; starts at schema.sortBy
  sortOrder: Ref<'asc' | 'desc'>       // starts at schema.sortOrder ?? 'asc'

  // CRUD — indexes are positions in `items`
  add(item: any): void
  update(index: number, patch: any): void   // merges the patch into the item
  remove(index: number): void
  move(from: number, to: number): void
  reset(): void                             // remove every item

  permissions: { canRead, canCreate, canUpdate, canDelete: ComputedRef<boolean> }
  destroy(): void                           // release the document (also runs on unmount)
}
```

## Basic usage

```typescript
const interviews = useProtoCollection(interviewsSchema)

// Add an item — give it an id yourself if you need one
interviews.add({
  id: crypto.randomUUID(),
  name: 'Alice',
  sentiment: 'positive',
  notes: 'Loves the product',
})

// Update / remove / reorder by index in `items`
interviews.update(0, { notes: 'Loves the product, will pay €49/mo' })
interviews.move(0, 1)
interviews.remove(1)

// Search
interviews.search.value = 'alice'
console.log(interviews.filtered.value) // only items matching 'alice' (when schema.searchable)

// Count
console.log(interviews.count.value)
```

## In templates

```vue
<script setup lang="ts">
const competitors = useProtoCollection(competitorsSchema)
const { isReady, items, search, filtered, count, add, remove } = competitors

function addCompetitor() {
  add({ id: crypto.randomUUID(), name: 'New Co' })
}
</script>

<template>
  <div v-if="isReady">
    <!-- Search -->
    <UInput v-model="search" placeholder="Search competitors…" />

    <!-- List -->
    <div v-for="item in filtered" :key="item.id">
      <span>{{ item.name }}</span>
      <UButton icon="i-lucide-trash" @click="remove(items.indexOf(item))" />
    </div>

    <!-- Add -->
    <UButton @click="addCompetitor">Add Competitor</UButton>

    <!-- Count badge -->
    <UBadge>{{ count }}</UBadge>
  </div>
</template>
```

`filtered` and `sorted` hold the same item objects as `items`, so `items.indexOf(item)` gives the index the CRUD operations need.

## Item structure

Items are stored exactly as you add them, and read back merged over `schema.defaults` (so a field added to the schema later reads its default). protokit does not generate ids; `ProtoCrudList` adds `id: Date.now()` to the items it creates.

## Search behavior

When `schema.searchable` is `true` and `search.value` is non-empty, `filtered` keeps the items where any of `schema.searchFields` (every field key when omitted) contains the search string, case-insensitive. Values of any type are compared as strings.

## Sort behavior

`sorted` applies after `filtered`. It is sorted by `sortKey` (insertion order while it is empty), with items missing the key last:

```typescript
competitors.sortKey.value = 'threat'
competitors.sortOrder.value = 'desc'
// competitors.sorted.value is now ordered by threat, highest first
```

Set the initial order with `sortBy` / `sortOrder` on the schema.

## Max items

If `schema.maxItems` is set, `add()` silently does nothing when the limit is reached. Check `count.value >= schema.maxItems` to show a "limit reached" message in UI.

## Low-level: `useProtoList`

`useProtoCollection` wraps `useProtoList`, which works on any `Y.Array` in a document you already have:

```typescript
function useProtoList<T>(
  doc: Y.Doc,
  key: string,                     // Y.Array name
  options?: {
    defaults?:   T                 // merged under every item on read
    maxItems?:   number
    version?:    number            // see Collections → Schema migration
    migrations?: SchemaMigrations
    waitFor?:    Ref<boolean>      // run migrations once this is true (pass the doc's isReady)
  },
): UseProtoListReturn<T>
```

`useProtoList` returns `{ items, add, update, remove, move, reset, count, dataArray }` — the same index-based CRUD, without search, sort, or permissions. `dataArray` is the underlying `Y.Array`.
