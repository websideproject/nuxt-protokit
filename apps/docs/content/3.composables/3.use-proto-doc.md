# `useProtoDoc`

Manages the complete lifecycle of a Y.js document. Handles reference counting, IndexedDB persistence (optionally encrypted), BroadcastChannel tab sync, server backup push, snapshot creation, and corruption detection/recovery.

You rarely need to call this directly — `usePrototype` calls it internally. Use `useProtoDoc` when you need direct access to the `Y.Doc` object, or one document shared by several tools.

## Signature

```typescript
function useProtoDoc(
  docKey: string,
  options?: {
    enableIndexedDB?: boolean   // default: true
    enableBroadcast?: boolean   // default: true
    skipAutoCleanup?: boolean   // default: false
    disableSync?: boolean       // default: false — override global serverSync config
    encryption?: { password: string } | { key: CryptoKey }  // AES-GCM at rest, see Encryption
  }
): UseProtoDocReturn
```

## Return value

```typescript
interface UseProtoDocReturn {
  doc:      Y.Doc
  isReady:  Ref<boolean>   // true once IndexedDB has loaded
  destroy:  () => void     // manually trigger cleanup (ref-counted)
}
```

## Document caching

`useProtoDoc` maintains a **module-level reference-counted cache**. If two components call `useProtoDoc('my-tool')` simultaneously, they receive the **same `Y.Doc` instance**. The document is destroyed only when all consumers have unmounted.

```typescript
// Component A and Component B share the same Y.Doc
const { doc: docA } = useProtoDoc('idea-123')
const { doc: docB } = useProtoDoc('idea-123')
console.log(docA === docB) // true
```

This is safe and intended — it enables multiple components to observe and modify the same document simultaneously, with Y.js merging changes automatically.

## Lifecycle

```
Component mounts
      │
      ▼
useProtoDoc('key')
      │
      ├── Check cache: existing doc? → return cached + increment ref count
      │
      └── New doc:
            ├── new Y.Doc()
            ├── new IndexeddbPersistence('proto:key', doc)   (EncryptedIdbPersistence('proto:enc:key') with encryption)
            │     └── loads stored data from browser DB
            ├── isReady = true  ← when IndexedDB has loaded
            ├── new BroadcastChannel('proto:key')
            │     └── notifies other tabs of updates
            └── if serverSync enabled:
                  ├── push full doc state + create snapshot once IndexedDB has loaded
                  └── again 30 s after the last local change

Component unmounts
      │
      └── decrement ref count
            └── if ref count === 0:
                  ├── clear debounced server push timer
                  ├── close BroadcastChannel
                  ├── destroy the IndexedDB provider (the stored data stays)
                  ├── destroy the Y.Doc
                  └── remove from cache
```

## Server sync

Server sync is controlled by the `protokit.serverSync` option in `nuxt.config.ts`. When enabled, `useProtoDoc` pushes the **full** document state once IndexedDB has loaded, and again **30 seconds** after the last local change. Errors (offline, 401, 404) are swallowed. The client never pulls from the server in normal use — only to [restore a corrupted document](/offline-first/corruption-recovery) — so the server is a backup, not a channel between devices:

```
Client                                Server (yjs-sync or compatible)
──────                                ───────────────────────────────
POST {baseUrl}/sync  ──────────────►  Stores binary Y.js updates
POST {baseUrl}/snapshots/create ───►  Creates deduplicated JSON snapshot
```

### Global config

```typescript
// nuxt.config.ts
protokit: {
  serverSync: true,                    // default — enabled, baseUrl: '/api/yjs'
  serverSync: false,                   // disabled — zero HTTP calls made
  serverSync: { baseUrl: '/api/yjs' }, // custom server base URL
}
```

### Per-document override

Pass `disableSync: true` to suppress server sync for one specific document, regardless of global config. Useful for public demo tools or scratch pads that should not accumulate server snapshots:

```typescript
// This doc never syncs to the server, even if serverSync: true globally
const { doc, isReady } = useProtoDoc('public-demo', { disableSync: true })
```

The document still persists to IndexedDB locally.

### What happens when sync is disabled

- No `POST /api/yjs/sync` calls are made
- No `POST /api/yjs/snapshots/create` calls are made
- If IndexedDB corruption occurs, the recovery modal shows only "Start fresh" (no server backup to restore from)
- Local IndexedDB + BroadcastChannel tab sync work normally

## BroadcastChannel tab sync

When a doc is updated in one browser tab, `useProtoDoc` broadcasts the update to all other tabs via `BroadcastChannel`. Other tabs apply the update to their in-memory `Y.Doc` immediately — no round-trip to the server.

This means: open the same tool in two tabs, type in one — the other updates in real time, offline.

## Readiness guard

Always wait for `isReady` before reading field values:

```typescript
const { doc, isReady } = useProtoDoc('my-tool')

watch(isReady, (ready) => {
  if (ready) {
    const fieldsMap = doc.getMap('my-tool')   // usePrototype keeps a schema's fields in Y.Map '<schema.key>'
    console.log('stored MRR:', fieldsMap.get('mrr'))
  }
}, { immediate: true })
```

In templates, guard with `v-if`:

```vue
<ClientOnly>
  <MyTool v-if="isReady" :doc="doc" />
  <USkeleton v-else />
</ClientOnly>
```

## The `ClientOnly` requirement

IndexedDB and `BroadcastChannel` only run in the browser. On the server, `useProtoDoc` creates an empty document whose `isReady` never becomes `true`, so a server render can only show the loading state. Wrap components that use `useProtoDoc` (or `usePrototype`) in `<ClientOnly>` with a fallback skeleton:

```vue
<template>
  <ClientOnly>
    <ProtoTool :schema="mySchema" />
    <template #fallback>
      <div class="animate-pulse">Loading…</div>
    </template>
  </ClientOnly>
</template>
```

## Accessing the raw Y.Doc

```typescript
const { doc } = useProtoDoc('my-tool')

// Read a value directly (the fields of a schema with key 'my-tool')
const fieldsMap = doc.getMap('my-tool')
const mrr = fieldsMap.get('mrr')

// Write a value directly (in a Y.js transaction)
doc.transact(() => {
  fieldsMap.set('mrr', 15000)
})

// Observe changes
fieldsMap.observe(event => {
  console.log('changed keys:', [...event.keysChanged])
})
```

## Namespace cleanup utilities

Two utilities are exported alongside `useProtoDoc` for cleaning up IndexedDB stores on logout or tenant switch. See the [Multi-tenant & per-user isolation](/offline-first/multi-tenant-isolation) guide for full context and security considerations.

### `clearProtoNamespace(namespace)`

Tears down all in-memory docs and deletes all IndexedDB stores whose key starts with `proto:<namespace>:`.

```typescript
await clearProtoNamespace(`${tenantId}:${userId}`)
```

Uses `indexedDB.databases()` to discover stores from previous sessions. Available in Chromium and Safari. On Firefox, only the current session's in-memory docs are cleaned up — stores from previous page loads remain on disk.

### `clearProtoKeys(namespace, schemaKeys)`

Cross-browser alternative: enumerate the schema keys to clean up explicitly. Works in all browsers including Firefox.

```typescript
import { mySchema, otherSchema } from '~/schemas'

await clearProtoKeys(`${tenantId}:${userId}`, [mySchema.key, otherSchema.key])
```

Use this when Firefox support is required, or when you want precise control over which stores are deleted.

## Pinia store integration

By default `useProtoDoc` registers an `onUnmounted` hook that releases the document. Inside a Pinia store that hook attaches to whichever component first used the store, so the document would be destroyed when that component unmounts — while the store lives on. Pass `skipAutoCleanup: true` and release it yourself if ever needed:

```typescript
// ❌ Wrong — the document is destroyed when the first component using the store unmounts
defineStore('myStore', () => {
  const { doc, isReady } = useProtoDoc('my-tool')
  return { doc, isReady }
})

// ✅ Correct — the store owns the document's lifetime
defineStore('myStore', () => {
  const { doc, isReady, destroy } = useProtoDoc('my-tool', { skipAutoCleanup: true })
  return { doc, isReady, destroy }   // call destroy() if the store is ever disposed
})
```
