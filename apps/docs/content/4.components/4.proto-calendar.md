## Overview

`ProtoCalendar` is a fully self-contained calendar component built on top of `useProtoCalendar`. It provides:

- **Three views**: Month, Week, and Day
- **Drag to move**: Pointer Events–based drag in all three views with a floating ghost preview
- **Drag to resize**: Bottom-handle drag in week/day views for timed events; right-edge handle in all views for all-day and multi-day events
- **Multi-day events**: Span across days in all views; resize from the right edge to extend or shorten the span
- **Range selection**: Click-drag on an empty grid slot to select a time range and pre-fill a new event
- **Overlapping event layout**: Google Calendar–style side-by-side columns for overlapping timed events
- **All-day events**: Separate band in week and day views; resizable across day columns
- **External drops**: Accept HTML5 drag payloads from outside the calendar (e.g. a task panel)
- **Y.js CRDT persistence**: IndexedDB storage and BroadcastChannel cross-tab sync
- **Collaborative**: Multiple tabs see each other's events in real time

## Quick Start

```vue
<template>
  <ProtoCalendar doc-key="my-calendar" class="h-screen" />
</template>
```

That's it. The component manages its own data layer internally.

## `useProtoCalendar` Composable

Use the composable directly when you need programmatic control over calendar events.

```typescript
const {
  events,       // Ref<CalendarEvent[]>
  addEvent,     // (event: Omit<CalendarEvent, 'id'>) => void
  updateEvent,  // (id: string, patch: Partial<CalendarEvent>) => void
  removeEvent,  // (id: string) => void
  moveEvent,    // (id: string, newStartAt: string, newEndAt: string) => void
  isReady,      // Ref<boolean>
  doc,          // Y.Doc
} = useProtoCalendar({
  docKey: 'my-calendar',
  disableSync: false,
})
```

## `CalendarEvent` Type

```typescript
interface CalendarEvent {
  id: string           // auto-generated UUID
  title: string
  startAt: string      // local ISO datetime: "YYYY-MM-DDTHH:mm:ss"
  endAt: string        // local ISO datetime — must be >= startAt
  allDay: boolean
  color: CalendarColor
  description: string
  location: string
  linkedTaskId: string // optional: ID of an external item linked to this event
}
```

Dates use **local time ISO strings** (not UTC) to avoid timezone drift across sessions.

`linkedTaskId` is an opaque string your app controls. The calendar stores it but does not interpret it. Use it to prevent the same external item from being scheduled more than once (see [External Drops](#external-drops) below).

## Integration with Other Proto Tools

Share a single Y.Doc between a calendar and other tools using `existingDoc`:

```typescript
const { doc } = useProtoDoc('shared-workspace')

// Both tools store their data in the same Y.Doc
const calendar = useProtoCalendar({ existingDoc: doc })
const collection = useProtoCollection(schema, { existingDoc: doc })
```

## Drag and Drop

### Month View — Move with Ghost

The month view uses the Pointer Events API (`pointerdown` / `pointermove` / `pointerup`) for event moves. When you start dragging an event:

1. The original event fades to 40% opacity.
2. A floating tooltip ghost follows the cursor, showing the event title and the destination date (e.g. "→ Mar 15").
3. The destination cell highlights in blue as the pointer enters it.
4. Releasing the pointer commits the move by emitting `eventMove`.

### Month View — Multi-day Resize

Every event pill in the month view shows a right-edge resize handle on hover (on the last day of the event). Dragging this handle:

1. Shows a floating tooltip following the cursor with the new end date (e.g. "Ends Mar 18").
2. Highlights the destination cell in green.
3. Commits the change on `pointerup` by emitting `eventMove` with an updated `endAt`.

The resize is blocked from moving before the event's start date.

### Week and Day Views — Move

Uses the Pointer Events API. Dragging snaps to 15-minute intervals. In week view, horizontal movement changes the day while vertical movement changes the time. `touch-action: none` ensures the drag works on touch devices without interfering with scroll.

A semi-transparent ghost overlay follows the pointer during the drag. The original event fades to 25% opacity. The move is committed on `pointerup` via `eventMove`.

### Week and Day Views — Timed Event Resize

Hover over a timed event in week or day view to reveal a resize handle at the bottom edge (cursor changes to `ns-resize`). Dragging the handle extends or shortens the event duration. It snaps to 15-minute intervals with a 15-minute minimum.

A ghost overlay shows the new end time live while dragging. The resize is committed on `pointerup` via `eventMove`.

### Week View — All-day Event Resize

All-day events in the all-day band also support right-edge resizing. Hover over an all-day event to reveal a handle on the right edge of its last day column (cursor changes to `ew-resize`). Dragging the handle left or right:

1. Highlights the spanned columns in the all-day band.
2. Commits the change on `pointerup` via `eventMove` with the updated `endAt` date.

The resize cannot move the end date before the event's start date.

### All-day ↔ Timed Conversion

In week and day views, you can convert events between timed and all-day:

- **Timed → All-day**: Drag a timed event upward past the time grid into the all-day band. The band highlights and a ghost label appears. Releasing converts the event to all-day via `eventUpdate`.
- **All-day → Timed**: Drag an all-day event from the band down into the time grid. It converts to a one-hour timed event at the drop position via `eventUpdate`.

### Click Suppression

After any pointer drag (move or resize), the browser fires a `click` event on `pointerup`. The calendar suppresses this for 300 ms so the edit modal does not open immediately after a drag.

## Range Selection

In week and day views, clicking and dragging on empty grid space opens an event creation flow pre-filled with the selected time range:

1. `pointerdown` on an empty cell records the start time.
2. `pointermove` draws a selection ghost showing the range label (e.g. "9:00 – 10:30").
3. `pointerup` emits `rangeSelect(startAt, endAt)`, which `ProtoCalendar` uses to open the create modal with those times pre-filled.

The minimum range is 15 minutes. Dragging upward is clamped to the start time.

## External Drops

All three views emit `externalDrop(startAt, endAt, allDay, data)` when an HTML5 drag originating outside the calendar is dropped onto the calendar. This lets you wire up a task list or any draggable sidebar.

```vue
<ProtoCalendar
  @external-drop="onExternalDrop"
/>
```

```typescript
function onExternalDrop(startAt: string, endAt: string, allDay: boolean, data: string) {
  // `data` is whatever was set via dataTransfer in the source dragstart handler
  const task = JSON.parse(data)
  addEvent({
    title: task.title,
    startAt,
    endAt,
    allDay,
    color: task.color ?? 'blue',
    description: '',
    location: '',
    linkedTaskId: task.id, // prevents the task from being scheduled twice
  })
}
```

To prevent duplicate scheduling, check `linkedTaskId` before allowing a task to be dragged:

```typescript
const scheduledTaskIds = computed(() =>
  new Set(events.value.map(e => e.linkedTaskId).filter(Boolean))
)

// In template: disable dragging for scheduled tasks
:draggable="!scheduledTaskIds.has(task.id)"
```

## Color Palette

18 colors are available via the `color` field on each event:

`red` · `orange` · `amber` · `yellow` · `lime` · `green` · `emerald` · `teal` · `cyan` · `sky` · `blue` · `indigo` · `violet` · `purple` · `fuchsia` · `pink` · `rose` · `neutral`

Colors are rendered via hardcoded hex values (`CALENDAR_COLOR_HEX`) and `color-mix()` so they work regardless of whether Tailwind CSS variables are available at runtime.
