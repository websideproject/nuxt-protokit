## Overview

`ProtoCalendar` is a fully self-contained calendar component built on top of `useProtoCalendar`. It provides:

- **Three views**: Month, Week, and Day
- **Drag-and-drop**: Cell-to-cell in month view (HTML5 DnD), time-snapping (15 min) in week/day views (Pointer Events API)
- **Overlapping event layout**: Google Calendar–style side-by-side columns
- **All-day events**: Separate band in week and day views
- **Y.js CRDT persistence**: IndexedDB storage + BroadcastChannel cross-tab sync
- **Collaborative**: Multiple tabs see each other's events in real time

## Quick Start

```vue
<template>
  <ProtoCalendar doc-key="my-calendar" class="h-screen" />
</template>
```

That's it. The component manages its own data layer internally.

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `docKey` | `string` | `'proto-calendar'` | IDB document key |
| `namespace` | `string` | — | Optional namespace prefix for multi-tenant isolation |
| `existingDoc` | `Y.Doc` | — | Pass a shared Y.Doc to co-locate with other tools |
| `initialView` | `'month' \| 'week' \| 'day'` | `'month'` | Starting view |
| `initialDate` | `string` | today | ISO date string for the initial date |
| `disableSync` | `boolean` | `false` | Disable server sync (use local IDB only) |

## `useProtoCalendar` Composable

Use the composable directly when you need programmatic control over calendar events.

```typescript
const {
  events,       // Ref<CalendarEvent[]>
  addEvent,     // (event: Omit<CalendarEvent, 'id'>) => void
  updateEvent,  // (id: string, patch: Partial<CalendarEvent>) => void
  removeEvent,  // (id: string) => void
  moveEvent,    // (id: string, newStartAt: string, newEndAt: string) => void
  isReady,      // Ref<boolean>
  doc,          // Y.Doc
} = useProtoCalendar({
  docKey: 'my-calendar',
  disableSync: false,
})
```

## `CalendarEvent` Type

```typescript
interface CalendarEvent {
  id: string          // auto-generated UUID
  title: string
  startAt: string     // local ISO datetime: "YYYY-MM-DDTHH:mm:ss"
  endAt: string       // local ISO datetime — must be >= startAt
  allDay: boolean
  color: CalendarColor
  description: string
  location: string
}
```

Dates use **local time ISO strings** (not UTC) to avoid timezone drift across sessions.

## Integration with Other Proto Tools

Share a single Y.Doc between a calendar and other tools using `existingDoc`:

```typescript
const { doc } = useProtoDoc('shared-workspace')

// Both tools store their data in the same Y.Doc
const calendar = useProtoCalendar({ existingDoc: doc })
const collection = useProtoCollection(schema, { existingDoc: doc })
```

## Drag and Drop

### Month View
Uses the HTML5 Drag and Drop API. Drag an event from one day cell to another to move it. The time of day is preserved; only the date changes.

### Week and Day Views
Uses the Pointer Events API (`pointerdown` / `pointermove` / `pointerup`). Dragging snaps to 15-minute intervals. In week view, horizontal movement changes the day while vertical movement changes the time. `touch-action: none` ensures the drag works on touch devices without interfering with scroll.

## Color Palette

18 colors are available via the `color` field on each event:

`red` · `orange` · `amber` · `yellow` · `lime` · `green` · `emerald` · `teal` · `cyan` · `sky` · `blue` · `indigo` · `violet` · `purple` · `fuchsia` · `pink` · `rose` · `neutral`

Color classes are defined as full literal strings in `COLOR_CLASSES` so Tailwind can statically scan and include them in the build.
