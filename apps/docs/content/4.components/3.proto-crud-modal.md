# `ProtoCrudModal`

A modal editor for a single collection item. Features:

- While a **new** item is being filled in, the form is saved as a draft (debounced 400 ms) to `Y.Map 'draft:{draftKey}'` in the document
- A Resume / Discard banner when the modal opens on an unfinished draft
- Two-column fields for wide modals (`modalSize` `'lg'` and wider)
- Validation with the collection's `validate`, per field or as one message
- Works with all field types, including `linked-responses`

## When to use it

Set `editMode: 'modal'` on a `CollectionSchema` to have `ProtoCrudList` open `ProtoCrudModal` for **Add** and for the edit button. You rarely need to instantiate `ProtoCrudModal` directly.

```typescript
collections: {
  interviews: {
    key: 'interviews',
    title: 'Interview',          // modal title: "Add Interview" / "Edit Interview"
    itemLabel: item => item.participant,
    fields: { /* … */ },
    defaults: { /* … */ },
    editMode:  'modal',          // triggers ProtoCrudModal
    modalSize: '3xl',
  }
}
```

## Props (when using directly)

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `open` | `boolean` (`v-model:open`) | `false` | Controls modal visibility |
| `schema` | `CollectionSchema` | required | The collection schema (fields, defaults, validate, modalSize) |
| `editData` | `Record<string, any> \| null` | — | Item to edit; omit or `null` to add a new one |
| `doc` | `Y.Doc` | required | The Y.js document the draft is stored in |
| `draftKey` | `string` | required | Name of the draft `Y.Map` (`draft:<draftKey>`). `ProtoCrudList` passes the collection's `key` |
| `collectionItems` | `Record<string, any[]>` | — | Collection arrays for `linked-responses` fields |

## Emits

| Event | Payload | Description |
|-------|---------|-------------|
| `save` | `Record<string, any>` | The form data when the user clicks **Add** / **Save Changes** and validation passes |
| `cancel` | — | The user clicked **Cancel** |

The modal closes itself on save and on cancel.

## Draft persistence

When a user starts a new item and closes the modal without saving, what they typed is kept as a draft. Editing an existing item keeps no draft.

**Storage location:** `Y.Map 'draft:{draftKey}'` inside the document — one draft per `draftKey`, so one per collection under `ProtoCrudList`.

Because drafts live in the Y.js document (backed by IndexedDB), they:
- Survive page refreshes and browser restarts
- Persist offline
- Are part of the document's server backup when `serverSync` is on

**Draft banner:** The next time the modal opens to add an item, if a draft exists, a banner offers it:

```
┌─────────────────────────────────────────────────────┐
│ Resume draft?                                       │
│ You have an unsaved draft from a previous session.  │
│                              [Resume]  [Discard]    │
└─────────────────────────────────────────────────────┘
```

**Resume** fills the form with the draft. **Discard** deletes the draft and starts from the schema's `defaults`. Saving the item also deletes the draft.

## Layout behavior

| `modalSize` | Layout |
|-------------|--------|
| not set, `sm`, `md` | Single-column fields |
| `lg`, `xl`, `2xl`, `3xl`, `4xl`, `5xl` | Two-column fields (`linked-responses` spans both) |

## Tailwind max-width mapping

| `modalSize` | Max width |
|-------------|-----------|
| `sm` | `max-w-sm` |
| `md` | `max-w-md` |
| `lg` | `max-w-lg` |
| `xl` | `max-w-xl` |
| `2xl` | `max-w-2xl` |
| `3xl` | `max-w-3xl` |
| `4xl` | `max-w-4xl` |
| `5xl` | `max-w-5xl` |

Without `modalSize`, the modal keeps Nuxt UI's default width.

## `useProtoDraft`

The draft composable, used internally by `ProtoCrudModal`:

```typescript
function useProtoDraft(
  doc:      Y.Doc,
  draftKey: string,
  defaults: Record<string, any>,
): {
  hasDraft:   Ref<boolean>                         // reactive, follows the Y.Map
  saveDraft:  (data: Record<string, any>) => void  // write fields + mark the draft present
  loadDraft:  () => Record<string, any>            // defaults overlaid with the draft (or just defaults)
  clearDraft: () => void
}
```

You can use `useProtoDraft` directly in your own editors:

```typescript
const { doc } = useProtoDoc('my-tool')
const { hasDraft, saveDraft, loadDraft, clearDraft } =
  useProtoDraft(doc, 'new-interview', { participant: '', notes: '' })

const formData = ref(loadDraft())

// Auto-save as the user types
watch(formData, data => saveDraft(data), { deep: true })

function submit() {
  // …save formData.value somewhere
  clearDraft()
}
```
