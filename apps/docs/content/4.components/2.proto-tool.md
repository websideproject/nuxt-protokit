# `ProtoTool`

The main entry point component. Given a `PrototypeSchema`, it renders the complete tool UI: form, results, visualizations, collections, and action toolbar. All Y.js persistence is handled internally.

![ProtoTool rendering the break-even calculator: form, result card and progress visualization](/screenshots/break-even-1440.png)

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `schema` | `PrototypeSchema` | required | The tool schema object |
| `doc` | `Y.Doc` | — | Use an existing Y.Doc (shared with other tools). The tool treats it as loaded, and ignores `docKey`, `namespace`, `encryptionPassword` and `disableSync` |
| `docKey` | `string` | `schema.key` | Y.js document key — override to run multiple independent instances |
| `namespace` | `string` | — | Namespace prefix for per-user / per-tenant isolation. Resulting key: `proto:<namespace>:<docKey>`. See [Multi-tenant isolation](/offline-first/multi-tenant-isolation). |
| `encryptionPassword` | `string` | — | Encrypt the IndexedDB store with a key derived from this password. See [Encryption at rest](/offline-first/encryption) |
| `disableSync` | `boolean` | `false` | Force local-only mode for this tool, regardless of the global `protokit.serverSync` config |

The props are read once, when the tool sets up. To switch a mounted tool to another document (a new `namespace` or `docKey`), give it a `:key` that changes with them.

## Basic usage

```vue
<template>
  <ClientOnly>
    <ProtoTool :schema="breakEvenSchema" />
  </ClientOnly>
</template>
```

## Multiple instances of the same schema

```vue
<template>
  <!-- Two independent instances with separate storage -->
  <div class="grid grid-cols-2 gap-6">
    <ClientOnly>
      <ProtoTool :schema="breakEvenSchema" doc-key="break-even-optimistic" />
    </ClientOnly>
    <ClientOnly>
      <ProtoTool :schema="breakEvenSchema" doc-key="break-even-conservative" />
    </ClientOnly>
  </div>
</template>
```

## Local-only / demo tools

Add `disable-sync` to suppress server sync for a specific tool, regardless of the global `protokit.serverSync` config. The tool still saves to the user's local IndexedDB — inputs survive page refresh. Only the server push is skipped.

```vue
<!-- Public demo — persists locally, never pushes to server -->
<ClientOnly>
  <ProtoTool :schema="demoSchema" disable-sync />
</ClientOnly>
```

This is the right choice for:
- Public marketing pages with embedded demo tools (you don't want every visitor's data on your server)
- Scratch pad tools that are intentionally ephemeral beyond the current browser
- Isolated test instances in development

## Rendering logic

Until the document has loaded, `ProtoTool` shows a spinner. Then it renders, in this order:

1. **Form** — with `sections`, one card per section; otherwise one card headed by the schema's `title`, `icon` and `description`
2. **Results** — one card per `schema.results` entry: its title and badge, then its stats in a `ProtoStatGrid` (skipped while `showWhen` is false)
3. **Visualizations** — one card with a `ProtoViz` per entry in `schema.visualizations`
4. **Cards** — `schema.cards` in a two-column grid
5. **Collections** — one `ProtoCrudList` per entry in `schema.collections`
6. **Reset button** — always; it resets the fields and empties every collection, without asking
7. **Action toolbar** — `ProtoActionBar` if `schema.actions` is defined

If `schema.layout` is defined, steps 1–6 are replaced by `ProtoDashboard`, which renders the custom tab/row/column layout; the action toolbar still follows it.

`ProtoTool` does not apply `permissions` guards, and does not mount `ProtoCorruptionModal` — mount that once in `app.vue`.

## Custom layout delegation

```typescript
// When schema.layout is defined:
const mySchema = definePrototype({
  key: 'interviews',
  layout: {
    tabs: [
      { id: 'questions',  label: 'Questions',  … },
      { id: 'interviews', label: 'Interviews', … },
      { id: 'patterns',   label: 'Patterns',   … },
    ]
  },
  // rest of schema…
})
```

`ProtoTool` detects `schema.layout` and renders `ProtoDashboard` instead of the default sequential layout.

## `ClientOnly` wrapper

Wrap `ProtoTool` in `<ClientOnly>`. Its data lives in IndexedDB, so a server render can only show the spinner; a fallback skeleton is the nicer placeholder:

```vue
<ClientOnly>
  <ProtoTool :schema="mySchema" />
  <template #fallback>
    <div class="space-y-4 animate-pulse">
      <div class="h-10 bg-muted rounded" />
      <div class="h-10 bg-muted rounded" />
      <div class="h-24 bg-muted rounded" />
    </div>
  </template>
</ClientOnly>
```

## Using `usePrototype` for custom layout

If the built-in rendering doesn't fit your design, use `usePrototype` directly and compose your own UI:

```vue
<script setup lang="ts">
import type { PrototypeSchema } from '#protokit/types'

const props = defineProps<{ schema: PrototypeSchema }>()

const { state, derived, collections, computeContext, isReady, reset } =
  usePrototype(props.schema)

const badge = computed(() =>
  props.schema.results?.[0]?.badge?.(computeContext.value) ?? null)
</script>

<template>
  <ClientOnly>
    <div v-if="!isReady">Loading…</div>
    <template v-else>
      <!-- Completely custom layout -->
      <aside>
        <ProtoForm :fields="props.schema.fields" :model="state" :sections="props.schema.sections" />
      </aside>
      <main>
        <UBadge v-if="badge" :color="badge.color">{{ badge.label }}</UBadge>
        <!-- Custom charts, tables, whatever -->
      </main>
    </template>
  </ClientOnly>
</template>
```
