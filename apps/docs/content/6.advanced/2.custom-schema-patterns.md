# Schema Patterns

A cookbook of advanced patterns for real-world tool schemas. The snippets show the relevant keys of a `definePrototype({ … })` call.

## Pattern: Multi-threshold result badge

Use tiers to guide users toward a specific goal range:

```typescript
results: [
  {
    title: 'Coverage',
    badge: ({ derived }) => {
      const ratio = derived.coverageRatio
      if (ratio === null) return null
      if (ratio >= 5)   return { label: `${ratio.toFixed(1)}x — Excellent`, color: 'success' }
      if (ratio >= 3)   return { label: `${ratio.toFixed(1)}x — Healthy`,   color: 'primary' }
      if (ratio >= 1.5) return { label: `${ratio.toFixed(1)}x — Marginal`,  color: 'warning' }
      return                  { label: `${ratio.toFixed(1)}x — Critical`,   color: 'error' }
    },
    stats: ({ derived }) => [
      { label: 'Coverage', value: derived.coverageRatio === null ? '—' : `${derived.coverageRatio.toFixed(1)}x` },
    ],
  },
],
```

Returning `null` hides the badge entirely — useful when there is not enough data to form a verdict.

## Pattern: Null-safe connection with local fallback

Always guard against missing upstream data. Provide a local input field as a fallback so the tool remains useful standalone:

```typescript
import { formatPercent } from '#protokit/utils/formatters'

fields: {
  // Used when no upstream tool is connected
  localMonthlyRevenue: {
    type: 'number',
    label: 'Monthly Revenue (€)',
    default: 0,
    help: 'Taken from the Revenue tool when it shares this workspace',
  },
  monthlyCosts: { type: 'number', label: 'Monthly Costs (€)', default: 0 },
},

consumes: {
  upstreamRevenue: 'revenue-tool.monthlyRevenue',
},

results: [
  {
    title: 'Margin',
    stats: ({ fields, connections }) => {
      const revenue = connections.upstreamRevenue ?? fields.localMonthlyRevenue ?? 0
      const margin = revenue ? ((revenue - fields.monthlyCosts) / revenue) * 100 : null
      return [{ label: 'Margin', value: margin === null ? '—' : formatPercent(margin) }]
    },
  },
],
```

Consumed values reach `results`, `visualizations`, `cards` and `actions`; inside `derived` the `connections` object is still empty.

## Pattern: Collection-driven bar chart

Generate visualization data dynamically from CRUD items:

```typescript
collections: {
  categories: {
    key: 'categories',
    title: 'Budget Categories',
    itemLabel: c => c.name,
    fields: {
      name:   { type: 'text',   label: 'Category',           default: '' },
      amount: { type: 'number', label: 'Monthly Amount (€)', default: 0 },
    },
    defaults: { name: '', amount: 0 },
  },
},

derived: {
  totalBudget: {
    compute: ({ collections }) =>
      (collections.categories ?? []).reduce((sum, c) => sum + (c.amount ?? 0), 0),
  },
},

visualizations: [
  {
    type: 'bar-chart',
    title: 'Budget by Category',
    config: {
      type: 'bar-chart',
      data: ({ collections }) =>
        [...(collections.categories ?? [])]               // copy before sorting the live array
          .sort((a, b) => (b.amount ?? 0) - (a.amount ?? 0))
          .map(c => ({ label: c.name, value: c.amount ?? 0 })),
      unit: '€',
    },
  },
],
```

## Pattern: Linked question-response collection

For tools where you have a list of questions and a list of sessions/records — with one answer per question inside each session:

```typescript
collections: {
  questions: {
    key: 'questions',
    title: 'Questions',
    itemLabel: q => q.text,
    fields: {
      text:     { type: 'text',   label: 'Question Text', default: '' },
      category: { type: 'select', label: 'Category', default: 'open',
                  options: [
                    { value: 'open',   label: 'Open-ended' },
                    { value: 'rating', label: 'Rating' },
                    { value: 'yn',     label: 'Yes/No' },
                  ] },
    },
    defaults: { text: '', category: 'open' },
    validate: q => q.text?.trim() ? true : { text: 'Write the question.' },
    presets: [
      {
        id: 'discovery-pack',
        label: 'Discovery Questions',
        description: '3 open-ended questions for a first session',
        items: [
          { text: 'What is the biggest challenge you face with X?', category: 'open' },
          { text: 'How are you handling X today?',                  category: 'open' },
          { text: 'What have you tried that did not work?',         category: 'open' },
        ],
      },
    ],
    onboardingPresets: true,
  },

  sessions: {
    key: 'sessions',
    title: 'Session',
    itemLabel: s => s.participant || 'Session',
    fields: {
      participant: { type: 'text', label: 'Participant Name', default: '' },
      date:        { type: 'date', label: 'Date',             default: '' },
      overallRating: {
        type: 'segmented',
        label: 'Overall Rating',
        default: 'neutral',
        options: [
          { value: 'negative', label: '👎' },
          { value: 'neutral',  label: '😐' },
          { value: 'positive', label: '👍' },
        ],
      },
      tags: { type: 'tags', label: 'Key Themes', default: [] },
      // One textarea per question from the 'questions' collection
      responses: {
        type: 'linked-responses',
        label: 'Question Responses',
        default: [],
        sourceCollection: 'questions',
        sourceLabel: q => q.text,
        sourceBadge: q => q.category,
      },
      keyTakeaway: { type: 'textarea', label: 'Key Takeaway', default: '' },
    },
    defaults: { participant: '', date: '', overallRating: 'neutral', tags: [], responses: [], keyTakeaway: '' },
    editMode:  'modal',
    modalSize: '3xl',
  },
},

derived: {
  sessionCount: { compute: ({ collections }) => collections.sessions?.length ?? 0 },
  allThemes: {
    compute: ({ collections }) =>
      [...new Set((collections.sessions ?? []).flatMap(s => s.tags ?? []))],
  },
  positiveRate: {
    compute: ({ collections }) => {
      const sessions = collections.sessions ?? []
      return sessions.length
        ? sessions.filter(s => s.overallRating === 'positive').length / sessions.length
        : null
    },
  },
},

produces: {
  sessionCount: 'number',
  allThemes:    'string[]',
  positiveRate: 'number',
},
```

The questions' `id`s link the answers: `ProtoCrudList` gives each item it creates an `id`, and preset items get one when they are added.

## Pattern: Tab layout with live badges

Show real-time item counts on the tabs:

```typescript
layout: {
  tabs: [
    {
      id: 'questions',
      label: 'Questions',
      badge: ({ collections }) => collections.questions?.length
        ? { label: String(collections.questions.length), color: 'neutral' }
        : null,
      rows: [
        { cols: 1, items: [{ type: 'collection', collectionKey: 'questions', view: 'list' }] },
      ],
    },
    {
      id: 'sessions',
      label: 'Sessions',
      badge: ({ collections }) => collections.sessions?.length
        ? { label: String(collections.sessions.length), color: 'neutral' }
        : null,
      rows: [
        { cols: 1, items: [{ type: 'collection', collectionKey: 'sessions', view: 'list' }] },
      ],
    },
    {
      id: 'insights',
      label: 'Insights',
      rows: [
        { cols: 2, items: [
          { type: 'stats', resultIndex: 0 },
          { type: 'viz',   vizIndex: 0 },
        ] },
      ],
    },
  ],
}
```

## Pattern: Export and copy actions

```typescript
actions: [
  {
    type: 'copy-text',
    id: 'copy-questions',
    label: 'Copy Question List',
    icon: 'i-lucide-clipboard-list',
    text: ({ collections }) =>
      (collections.questions ?? [])
        .map((q, i) => `${i + 1}. ${q.text}`)
        .join('\n\n'),
  },
  {
    type: 'export-markdown',
    id: 'export-report',
    label: 'Export Full Report',
    icon: 'i-lucide-file-text',
    filename: 'session-report.md',
    content: ({ derived, collections }) => [
      `# Session Report`,
      ``,
      `**${derived.sessionCount} sessions completed**`,
      ``,
      `## Recurring Themes`,
      ...(derived.allThemes ?? []).map((t: string) => `- ${t}`),
      ``,
      `## Session Notes`,
      ...(collections.sessions ?? []).map((s: any) =>
        `### ${s.participant} — ${s.date}\n${s.keyTakeaway || '_No takeaway recorded._'}`,
      ),
    ].join('\n'),
  },
  {
    type: 'reset',
    id: 'reset',
    label: 'Reset All Data',
    icon: 'i-lucide-trash-2',
  },
]
```

`reset` runs immediately — there is no confirmation option.

## Pattern: Conditional field visibility

Hide fields that are not relevant given the current state:

```typescript
fields: {
  mode: {
    type: 'segmented',
    label: 'Mode',
    options: [
      { value: 'simple',   label: 'Simple' },
      { value: 'advanced', label: 'Advanced' },
    ],
    default: 'simple',
  },
  basicInput: {
    type: 'number',
    label: 'Basic Input',
    default: 0,
  },
  advancedInputA: {
    type: 'number',
    label: 'Factor A',
    default: 1,
    showWhen: values => values.mode === 'advanced',
  },
  advancedInputB: {
    type: 'number',
    label: 'Factor B',
    default: 1,
    showWhen: values => values.mode === 'advanced',
  },
},
```

## Pattern: Schema versioning

To change stored data in place — rename a field, change its type — bump `version` and add a `migrations` step (see [Field Types → Schema migration](/schemas/fields#schema-migration)). The data stays under the same key.

To start over instead, change the `key`. A new key is a new IndexedDB store, so users get a clean slate and the old data stays where it was:

```typescript
// v1 — original
const estimatorV1 = definePrototype({ key: 'cost-estimator', … })

// v2 — breaking change, fresh storage
const estimatorV2 = definePrototype({ key: 'cost-estimator-v2', … })
```

To carry values over to the new key, copy them once. Each schema key is its own document, so open both:

```typescript
// In a client plugin or onMounted
import { until } from '@vueuse/core'

async function migrateV1toV2() {
  const v1 = useProtoDoc('cost-estimator', { skipAutoCleanup: true })
  const v2 = useProtoDoc('cost-estimator-v2', { skipAutoCleanup: true })
  await until(() => v1.isReady.value && v2.isReady.value).toBe(true)

  const v1Fields = v1.doc.getMap('cost-estimator')
  const v2Fields = v2.doc.getMap('cost-estimator-v2')

  if (v1Fields.size > 0 && v2Fields.size === 0) {
    v2.doc.transact(() => {
      // Rename: oldName → newName
      v2Fields.set('newFieldName', v1Fields.get('oldFieldName'))
      // … copy remaining fields
    })
  }
  v1.destroy()
  v2.destroy()
}
```

When the tools share one workspace document instead, both maps live in it: `doc.getMap('cost-estimator')` and `doc.getMap('cost-estimator-v2')`.
